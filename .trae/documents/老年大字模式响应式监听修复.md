# 老年大字模式响应式监听修复 — 实施方案

## Context（为什么做这个改动）

spec 10.10.7 标注"任务5 老年大字模式验证 | 可立即启动验证"，但代码核查发现**响应式监听从未真正落地**：

1. **根因**：`CurrentModeKey` / `CurrentThemeKey`（[CommonModels.ets](file:///C:/Users/21132/Project/zhunong/common/src/main/ets/model/CommonModels.ets) 行 137-145）是普通 class，**缺少 `@ObservedV2` + `@Trace value` 装饰器**。ModeStore.setMode 行 35 `modeRef.value = mode` 只是普通赋值，不触发 UI 刷新。
2. **页面端**：3 个页面（farmer home_page / farmer setting / user setting）用 `@Local currentMode: string` + `aboutToAppear` 中 `await ModeStore.getMode()` 一次性读取，模式切换后其他已打开页面不刷新。
3. **spec 10.9.3.3 误报**：原 spec 规定 `@Consumer('currentMode')` 改造方案，spec 10.10 标记"✅ 已完成"实为误报——实际用 @Local+getMode 替代，丢失响应式。且 `@Consumer` 属 V1 联动语义，与 spec 10.10.4 "@StorageLink 全清"的 V2 路线冲突。

**预期结果**：模式切换后，所有已打开页面的字号/样式实时刷新（farmer home_page 的 30+ 处 isElderMode() 适配即时生效），无需重新进入页面。

## 修复方案

### 核心机制（经华为官方文档验证）

AppStorageV2.connect + @ObservedV2 + @Trace 是 V2 标准响应式全局状态模式：
> "如果修改的数据被 @Trace 装饰，该数据的修改会同步更新 UI。" —— [AppStorageV2 官方文档](https://device.harmonyos.com/cn/docs/apiref/harmonyos-guides/arkts-new-appstoragev2)

AppStorageV2.connect 同 key 返回**同一共享实例**，ModeStore.setMode 写入 modeRef.value 后，所有在 build() 中读取 modeRef.value 的组件自动刷新。

### 改造模式（isElderMode 调用点 0 改动）

**改造前**（一次性读取，不响应式）：
```typescript
@Local currentMode: string = AppConstants.MODE_STANDARD;
async aboutToAppear() { this.currentMode = await ModeStore.getMode(); }
private isElderMode(): boolean { return this.currentMode === AppConstants.MODE_ELDER; }
```

**改造后**（响应式监听）：
```typescript
@Local modeRef: CurrentModeKey = ModeStore.connectModeRef();
// 删除 aboutToAppear 中的 getMode()
private isElderMode(): boolean { return this.modeRef.value === AppConstants.MODE_ELDER; }
// build() 中 this.isElderMode() 调用点 0 改动
```

## 关键实现细节

### Step 1：CommonModels.ets 装饰器

```typescript
import { ObservedV2, Trace } from '@kit.ArkUI';  // 顶部新增

@ObservedV2
export class CurrentModeKey {
  @Trace value: string = '';
}

@ObservedV2
export class CurrentThemeKey {
  @Trace value: string = '';
}
```
其余 4 个 Key（AuthTokenKey/UserInfoKey/AdminInfoKey/AuthExpiredKey）不加——它们不参与 build() 响应式渲染。

### Step 2/3：ModeStore/ThemeStore 新增 connect 方法

```typescript
// ModeStore.ets
connectModeRef(): CurrentModeKey {
  return AppStorageV2.connect(CurrentModeKey, ModeStoreImpl.STORAGE_KEY,
    () => { const init = new CurrentModeKey(); init.value = AppConstants.MODE_STANDARD; return init; })!;
}
// ThemeStore.ets 同构 connectThemeRef()
```

### Step 4-6：页面改造要点

- import 增加 `CurrentModeKey`（+ `CurrentThemeKey` 若涉及主题）：从 'common' type 导入，已可用
- `@Local currentMode: string` → `@Local modeRef: CurrentModeKey = ModeStore.connectModeRef()`
- 删除 aboutToAppear 中 `this.currentMode = await ModeStore.getMode()`
- isElderMode() 实现改 `this.modeRef.value === AppConstants.MODE_ELDER`
- toggleMode/onModeChange 中删除 `this.currentMode = next/this.currentMode = mode`（setMode 已通过共享 ref 自动同步）
- build() 中直接引用 `this.currentMode` 处改为 `this.modeRef.value`（仅 setting.ets 有此类引用）
